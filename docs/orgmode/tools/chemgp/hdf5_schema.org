* HDF5 Layout

The ChemGP Rust examples write line-delimited records.
ChemGP's =scripts/jsonl_to_h5.py= turns them into HDF5 files with a fixed layout.
The ~plt-gp~ subcommands each read specific groups and attributes from this layout.

** Top-Level Groups

| Group | Contents |
|-------------------+--------------------------------------------------------------|
| ~grids/<name>~ | 2D arrays with attrs ~x_range~, ~y_range~, ~x_length~, ~y_length~ |
| ~<name>~ | Table: a root-level group of same-length 1D arrays (DataFrame columns) |
| ~paths/<name>~ | Ordered point sequences (~x~, ~y~ or ~rAB~, ~rBC~) |
| ~points/<name>~ | Point sets (~x~, ~y~ or ~pc1~, ~pc2~) |
| Root attrs | Metadata scalars (~conv_tol~, ~gp_e_mae~, etc.) |

** Group Details

*** ~grids~

Each grid is a 2D ~float64~ dataset. Attributes store axis info:

- ~x_range~ :: ~[x_min, x_max]~ (float64[2])
- ~y_range~ :: ~[y_min, y_max]~ (float64[2])
- ~x_length~ :: Number of x grid points (int)
- ~y_length~ :: Number of y grid points (int)

Named grids:

- ~energy~ :: True potential energy surface
- ~true_energy~ :: True surface, as the ~quality~ subcommand reads it
- ~gp_mean_N<n>~ :: GP mean from /n/ training points
- ~variance~ :: GP variance
- ~nll~, ~grad_norm~ :: Negative log-likelihood and the norm of its gradient

*** Tables

Each table is a group at the root of the file.
Its children are same-length 1D arrays, like DataFrame columns.
Three subcommands read the table named ~table~: ~convergence~, ~rff~ and ~profile~.
Tables often have these columns:

- ~oracle_calls~ :: Cumulative oracle evaluations
- ~max_fatom~, ~max_force~, ~force_norm~, ~ci_force~ :: Force convergence metrics
- ~energy~ :: Total energy at each step
- ~method~ :: String array identifying the optimizer
- ~d_rff~, ~energy_mae~, ~gradient_mae~ :: RFF sweep data

*** ~paths~

Each path is a group with ~x~ and ~y~ (or ~rAB~ and ~rBC~) arrays tracing a
reaction path on the 2D surface.

*** ~points~

Each point set is a group with coordinate arrays:

- ~x~, ~y~ :: Cartesian coordinates
- ~pc1~, ~pc2~ :: PCA projections (for FPS scatter)

Named sets: ~minima~, ~saddles~, ~endpoints~, ~training~, ~train_N<n>~, ~selected~, ~pruned~, ~optimum~.

* Schema per Plot Type

| Subcommand | Required groups/attrs |
|---------------+-----------------------------------------------------------|
| convergence | ~table~ (oracle_calls, force metric, method) and root ~conv_tol~ |
| surface | ~grids/energy~, optionally ~paths/*~ and ~points/*~ |
| quality | ~grids/true_energy~ and one or more ~grids/gp_mean_N<n>~, optionally ~points/train_N<n>~ |
| rff | ~table~ (d_rff, energy_mae, gradient_mae) and root ~gp_e_mae~, ~gp_g_mae~ |
| nll | ~grids/nll~, optionally ~points/optimum~ (log_sigma2, log_theta) and ~grids/grad_norm~ |
| sensitivity | ~slice~ (x), ~true_surface~ (E_true) and one or more of the three-by-three ~gp_ls{j}_sv{i}~ panels with E_pred and E_std, blank where missing |
| trust | ~slice~ (x, E_true, E_pred, E_std, in_trust) and ~points/training~, optionally root ~y_slice~ |
| variance | ~grids/energy~, ~grids/variance~ and ~points/training~, optionally ~points/minima~ and ~points/saddles~ |
| fps | ~points/selected~ (pc1, pc2), ~points/pruned~ (pc1, pc2) |
| profile | ~table~ (image, energy, method) |
| landscape | .con files in ~source_dir~ (not HDF5; delegates to plt-neb) |

* Filename Conventions

The ~surface~ and ~quality~ subcommands auto-detect energy clamping from the
input filename:

| Pattern in filename | ~clamp_lo~ | ~clamp_hi~ |
|---------------------+------------+------------|
| ~mb~ | -200 | 50 |
| ~leps~ | -5 | 5 |
| (other) | data min | data max |
